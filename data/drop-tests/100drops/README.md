# 100 auto-drops on the latest tensegrity structure

Raw TP4 accelerometer exports for the **100-auto-drop campaign** by @ctrhjk,
posted on [PR #67](https://github.com/vertical-cloud-lab/tensegrity-optimization/pull/67)
as four zips (`drop1.zip`–`drop4.zip`, 25 captures each).

First full-length (100-drop) campaign, on the latest structure with key-seat
housings at the top and a bottom vertex (**specimen ID not yet assigned** in
the posting comment). Two instrumentation changes vs the 30-drop `RW5F61`
run:

1. the base-plate single-axis sensor (CH5) is **taped** to the acrylic plate;
2. the bottom-vertex tri-axis is a **low-range unit**: CH6/CH7/CH8 full scale
   1002.0 / 991.1 / 989.1 G at ~10 mV/G.

The **trigger stayed on CH5** (1000 G). The channel table posted with the data
listed CH4 as the trigger, but @ctrhjk corrected this in a follow-up comment —
the 30-drop recommendation to move the trigger off the plate sensor was not
adopted this run.

## Recording setup

Drop height **13 in**, drops released automatically (median 20 s cadence,
range 14–21 s; the 100 events span ~31 min on 07/06/2026). DAQ as in the prior
series: 200 ms record, 125 kHz (8 µs), 25000 samples, 2 % (4 ms) pre-trigger.
All channels AC-coupled, ICP on, Half-Sine analysis.

## Files

`raw/100drops_Signal{1..100}.csv` — TP4 Time-Domain exports (header block,
then `Time, CH2..CH8 (G's)`). **All 100 captures are real drops** — no
spurious triggers, no sensor fall-offs; the impact lands at 4.01 ± 0.01 ms in
every record.

Known data issue: the bottom-vertex drop-axis channel **CH8 exceeds its
989.1 G full scale on 85/100 drops** (median raw peak 104.7 % FS); CH6/CH7
also touch full scale on some drops. BOT-derived amplitudes are
saturation-biased — see the analysis doc.
