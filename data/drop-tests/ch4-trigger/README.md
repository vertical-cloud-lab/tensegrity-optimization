# CH4-trigger validation — 50 auto-drops on `RW5F61`

Raw TP4 accelerometer exports for the **CH4-trigger 50-drop campaign** by
@ctrhjk, posted on
[PR #67](https://github.com/vertical-cloud-lab/tensegrity-optimization/pull/67)
(TP4 session `ch4 triggered-50 drops`).

The one change under test vs the 100-drop campaign: the DAQ **trigger moved
from the base-plate single-axis CH5 to the top-vertex tri-axis drop-axis
channel CH4** (level 1000 G) — the defensive upgrade recommended after the
30-drop and 100-drop runs, since CH5 is the one sensor with a fall-off
history. Everything else is unchanged: specimen **`RW5F61`** (cumulative
history now 180 conducted / 177 captured drops at 13 in), taped CH5 on the
base plate, low-range tri-axis (CH6–8) in the bottom-vertex housing, cable
tie-offs on both tri-axis sensors.

## Recording setup

Drop height **13 in**, drops released automatically (median 14 s cadence,
range 13–14 s; the 50 events span ~11 min on 07/06/2026). DAQ as in the prior
series: 200 ms record, 125 kHz (8 µs), 25000 samples, 2 % (4 ms) pre-trigger.
All channels AC-coupled, ICP on, Half-Sine analysis.

## Files

`raw/ch4trigger_Signal{1..50}.csv` — TP4 Time-Domain exports (header block,
then `Time, CH2..CH8 (G's)`). **All 50 captures are real drops** — no
spurious triggers, no sensor fall-offs; the CH4 trigger crossing sits at
3.896 ± 0.002 ms in every record (±1 sample of jitter).

Known data issue (carried over from the 100-drop run): the bottom-vertex
tri-axis is still the low-range unit — **CH8 exceeds its 989.1 G full scale
on 40/50 drops** (median raw peak 105 % FS); CH6/CH7 also cross full scale on
some drops. BOT-derived amplitudes remain saturation-biased.
