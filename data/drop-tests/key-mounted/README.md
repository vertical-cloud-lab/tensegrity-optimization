# Key-seat input-output drop tests (specimen `prc1kn`)

Raw TP4 accelerometer exports for the **key-seat mount validation** run by
@ctrhjk, posted on
[PR #67](https://github.com/vertical-cloud-lab/tensegrity-optimization/pull/67#issuecomment-4837240958).

This is a direct follow-up to the
[input-output (transmissibility) series](../input-output/README.md). The
instrumentation is the same input-output pair — a single-axis accelerometer on
the bottom acrylic plate is the **input**, a tri-axis accelerometer on the top
vertex is the **output**, and the bungees are removed. The **one** thing under
test here is the **output mount**: instead of a hand-applied hot-glue blob on a
rounded vertex, the tri-axis now seats in the printed **key-seat** pocket (the
"igloo" `accel_mount()` housing from #35). The goal is to check whether the
key-seat removes the mild within-run drift the hot-glue mount showed across five
cyclic drops in the prior series (which Edison attributed to mount creep, not
material softening).

The specimen `prc1kn` is a **deliberately-failed print** (bubbles in its TPU
cable); it is used only to exercise the mount + DAQ, **not** to compare geometry.

## Recording setup

One specimen, **five drops** (`Signal{1,2,3,5,6}` = drops 1…5; see file-name
note below), drop height **13 in**. Channels and DAQ are identical to the
input-output series.

| Channel | Sensor | Mount | Role | Full scale (G) | Sensitivity (mV/G) | Trigger |
|---|---|---|---|--:|--:|---|
| CH2 | tri-axis | vertex **key-seat** | output | 14492.8 | 0.69  | No |
| CH3 | tri-axis | vertex **key-seat** | output | 14992.5 | 0.667 | No |
| CH4 | tri-axis | vertex **key-seat** | output | 13624.0 | 0.734 | No |
| CH5 | single-axis | base plate (wax) | **input** | 9442.9 | 1.059 | **Yes** (1000 G) |

All channels AC-coupled, ICP on, Half-Sine waveform analysis. DAQ: record time
200 ms, 125 kHz (8 µs), 25000 samples, 2 % (4 ms) pre-trigger. The trigger is on
CH5 (the single-axis input on the base plate), as in the input-output series.

## Files

Each CSV is a TP4 Time-Domain export: a short header block, then columns
`Time (sec), CH2 Acc (G's), CH3 Acc (G's), CH4 Acc (G's), CH5 Acc (G's)`.

| File | Drop # |
|---|---|
| `raw/key_mounted_Signal1.csv` | 1 |
| `raw/key_mounted_Signal2.csv` | 2 |
| `raw/key_mounted_Signal3.csv` | 3 |
| `raw/key_mounted_Signal5.csv` | 4 |
| `raw/key_mounted_Signal6.csv` | 5 |

**File-name note:** the TP4 `Signal{n}` index is the *capture* number, not the
drop number, and it is **not contiguous** here. Drop 4's first capture
(`Signal4`) was discarded, so the five drops map to `Signal{1,2,3,5,6}` = drops
1…5. (Drop 3's video was accidentally deleted, but its CSV is intact.)

## Notes from @ctrhjk

1. The tri-axis output sensor is mounted in the printed **key-seat** (vertex
   housing); the single-axis input sensor is wax-mounted on the base plate.
2. No bungees attached to the drop-load (pretension removed), as in the
   input-output series.
3. The specimen is a failed print (TPU bubbles), used to validate the mount/DAQ.
4. **The accelerometer fell off during the run** — the key-seat press-fit alone
   was not enough to retain it. The five captured drops are clean; the plan is to
   add wax inside the housing to retain the sensor for future runs.
