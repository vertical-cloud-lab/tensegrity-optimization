# How to print the T3-prism (with tree-style supports) in Bambu Studio

A step-by-step **GUI** guide for printing the tensegrity T3-prism on the lab's
**Bambu Lab H2D**. It uses manually-baked **tree-style breakaway supports**
(no painted supports, no slicer-generated supports) — every overhanging
member, including the near-vertical TPU cables, is held up by slim branches
that are baked into the printable mesh and snapped off after printing. The
branches touch the part with a tiny contact tip (so they snap off without
tearing the part) and converge onto just a few feet on the plate (so there is
little build-plate buildup), in the style of Bambu Studio's tree supports.

There are two ways to print it. Start with **Path 1** (single-material PLA) to
prove out orientation/adhesion, then move to **Path 2** (PLA struts + TPU
cables) for the real part.

> The struts (1) and cables (2) are the two halves of the printable part; the
> pillars (3) are the snap-off supports. The pillars are **PLA either way** —
> they print on the same extruder as the struts and snap off after printing.

> **Where do the supports come from?** They are generated by ray-casting the
> printable mesh from the build plate's point of view and growing a tree of
> slim branches up to wherever the part hangs over empty plate (see
> [`generate_support_pillars.py`](generate_support_pillars.py)). A pre-built
> one for the PR #35 T3-prism is committed at
> `verification/t3-prism-pr35-pillars.stl`. To regenerate for a different
> mesh:
>
> ```bash
> python3 cad/print-supports/generate_support_pillars.py \
>     --stl t3-prism.stl --tree --spacing 4.0 --min_clearance 7.0 \
>     --merge_radius 22 --out pillars.stl
> ```

## Path 1 — quick single-material PLA test (one combined STL)

The fastest way to sanity-check orientation and bed adhesion. A ready-made
**part + pillars** mesh is already committed, so you only upload **one** file.

1. **Import the combined mesh.** Bambu Studio → drag
   [`verification/t3-prism-pr35-with-pillars.stl`](verification/t3-prism-pr35-with-pillars.stl)
   onto the plate (or **File → Import → Import 3MF/STL…**).
   - If you see a **"non-manifold edges / repair"** prompt, click **Repair**.
     This is expected — the part and the pillars are two separate solids that
     touch at the pillar tips, which trips the manifold checker. The repair is
     cosmetic and does not change the geometry that matters. (Slicing through
     the patched CLI does not require the repair; it is only the GUI mesh
     checker that flags it.)
2. **Pick the printer + filament.** Top bar: printer = **Bambu Lab H2D 0.4
   nozzle**, filament = **Bambu PLA Basic**.
3. **Orient.** The mesh is already laid down with the three bottom-triangle
   vertices on the plate (`z = 0`) and the pillars rising from the bed. If it
   loads on its side, select it and press **`A`** (Auto orient) or **Place on
   face** and pick the bottom-triangle face.
4. **Turn supports OFF.** Right panel → **Support → Enable support = OFF**.
   The pillars *are* the supports; you do not want the slicer adding its own.
5. **Brim for adhesion.** Right panel → **Others / Adhesion → Brim type =
   Outer brim only**, **Brim width = 5 mm**. Tensegrity nodes and pillar bases
   have tiny footprints, so the brim is cheap insurance against tip-over.
6. **Slice → inspect → print.** Slice, scroll the layer preview from the
   bottom up, and confirm each pillar rises from the plate to the underside of
   a member. Send to the H2D.
7. **Post-process.** After printing, **snap each branch off at its narrow
   contact tip** (the tip is the designed breakaway notch). Because the
   branches are thin and only touch the part with a ~0.6 mm tip, they peel
   away in one piece without tearing the member. Trim any nub flush.

## Path 2 — the real part: PLA struts + TPU cables (multiple STLs)

This is the multi-material print. You upload the part meshes **and** the
pillars STL, combine them into **one object made of several parts**, then
assign each part to the right filament.

### 2a. Load the filaments on the H2D

Top bar → set up two filaments:

- **Filament 1 = Bambu PLA Basic** (struts + pillars)
- **Filament 2 = Bambu TPU 85A** — click the **`+`** next to the filament
  list to add the second slot. On the H2D, the TPU slot must use the
  **TPU High Flow** nozzle option ("Direct Drive TPU High Flow") so the soft
  filament feeds reliably.

### 2b. Import the meshes and merge into one object

1. **Import all three meshes** (drag them all onto the plate, or **File →
   Import** each — see the "three STLs to upload" table above for direct
   download links):
   - [`t3-prism-struts.stl`](https://github.com/vertical-cloud-lab/tensegrity-optimization/blob/65d0d3f2b1d673f74755e1c8900af5af2500fc53/cad/t3-prism/t3-prism-struts.stl) → will become **PLA**
   - [`t3-prism-cables.stl`](https://github.com/vertical-cloud-lab/tensegrity-optimization/blob/65d0d3f2b1d673f74755e1c8900af5af2500fc53/cad/t3-prism/t3-prism-cables.stl) → will become **TPU**
   - [`t3-prism-pr35-pillars.stl`](verification/t3-prism-pr35-pillars.stl)
     → will become **PLA**
2. They import as **separate objects** that already share the same coordinate
   frame (they were authored in the same frame), so do **not** move them.
   Select all three (**Ctrl+A** or rubber-band them in the object list).
3. Right-click the selection → **Assemble** (a.k.a. **"Merge into one object
   as parts"**). They collapse into a single object with three sub-parts in
   the **Objects** list (the little tree on the left). Keeping them as parts
   of one object is what lets you give each part its own filament while they
   stay registered to each other.

   > If the GUI's **Assemble** entry isn't visible, the equivalent is
   > right-click → **Add Part → Load…** and add the cables and pillars onto
   > the struts object one at a time. Either way you end up with one object
   > whose tree lists *struts*, *cables*, and *pillars* as parts.

### 2c. Assign a filament to each part

In the **Objects** tree, click each sub-part and set its filament (right-click
the part → **Change filament**, or use the per-part filament dropdown / the
paint-bucket "Filament" tool):

| Part | Filament |
| ---- | -------- |
| struts / part body | **1 — PLA** |
| pillars | **1 — PLA** |
| cables | **2 — TPU** |

Spin the model and confirm only the cables show the TPU colour.

### 2d. Orientation, supports, brim

Same as Path 1:

- Three bottom-triangle vertices flat on the plate (`A` to auto-orient if
  needed).
- **Enable support = OFF** (the pillars are the supports).
- **Brim = outer only, 5 mm.**

### 2e. Slice, inspect, print

1. **Slice.** Expect a long estimate (~21 h for this part — TPU + the
   prime/wipe tower dominate). The slicer inserts a **prime/wipe tower**
   automatically for the PLA↔TPU changes; leave room for it on the plate.
2. **Inspect the preview.** Use the per-extruder colour view: PLA struts +
   pillars in one colour, TPU cables in the other. Walk the layers from the
   bottom and confirm each pillar reaches the underside it is meant to hold.
   (For reference, this is exactly what the committed
   `verification/t3-prism-pr35-mm-pillars-preview.png` shows.)
3. **Print**, then **snap the pillars off** at their tips as in Path 1.

## Tips & troubleshooting

- **"211 non-manifold edges" on import** → click **Repair**; it's expected
  where the pillars touch the part and is harmless. (Seen and confirmed
  harmless by @sgbaird.)
- **Supports too solid / hard to remove (broke the part last time)** → the
  supports are now generated with `--tree`, so the branches are thin (slice
  to walls only, near-hollow) and contact the part with a tiny ~0.6 mm tip
  that snaps off without tearing the member. If you still find them too
  tenacious, lower `--tip_d` (smaller contact) or `--branch_d` (thinner
  branch) when regenerating.
- **Too much buildup on the build plate** → tree mode merges the branches
  onto just a few feet (7 for the PR #35 T3-prism). Raise `--merge_radius`
  for even fewer feet, or `--min_clearance` to skip near-plate overhangs.
- **A branch looks like it doesn't reach a member** → regenerate the supports
  from the *current* mesh with `generate_support_pillars.py --stl … --tree`
  (the ray-cast mode lands each tip on the actual underside surface, including
  joint spheres); see [`README.md` §C/§D](README.md).
- **Supports going to the bottom-triangle vertices** → those vertices already
  sit on the plate, so a support there is redundant; the default
  `--min_clearance 7.0` now suppresses them. Lower it if you want them back.
- **TPU cable still sags** → confirm the cable part is on the **TPU High Flow**
  nozzle slot and that **Enable support is OFF** so the pillars (not the
  slicer's tree, which can't see vertical cylinders) are doing the work. The
  reasoning for why slicer-side supports cannot cover vertical cables is in
  [`README.md` §C](README.md).

A fully reproducible **headless CLI** version of both paths (used to generate
the committed previews and metrics) is documented in
[`verification/README.md`](verification/README.md).
