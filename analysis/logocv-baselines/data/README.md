# Inputs and outputs of the LOGO-CV baseline comparison

Everything here is either a verbatim copy with the provenance below, or
generated by a script in the parent directory.

## Vendored (verbatim) from the audit branch

Branch `claude/cv-signal-audit-20260922` at commit `6964ac2`, directory
`analysis/cv-signal-audit/data/`:

- `sim-features.csv`: one row per design-mapped article (46), with the six
  `sim_*` columns the simulation-feature runs append to the fit space (Tier C
  and Tier B transmissibility analogues, Tier C peak tendon energy and
  stroke, Tier B ringdown frequency and damping), from the #33 simulators
  (branch `copilot/explore-simulations-for-tensegrity` at `94e53a8`) run at
  the design's print geometry with the design-mean weighed mass, so reprint
  twins share identical features. Written by that branch's
  `compute_sim_features.py`. The `batch` column is the print session.
- `ax-runs/<run>/`: the Ax SAASBO leave-one-design-out runs, every one at
  256 NUTS samples / 512 warmup steps per fold, 35 design folds over 44
  articles, reprint pairs held out together, `torch.manual_seed(fold_index)`
  per fold, campaign code at `bbf7a62`, the campaign's round-5 snapshot:

  | directory | fit space | written by (on the audit branch) |
  |---|---|---|
  | `full-nuts-rerun/` | the campaign's 12 parameters | `rerun_logocv_full_nuts.py` (the manuscript's `t3-prism-bo-round5-logocv.csv`) |
  | `ablation-six-param/` | 6: five shape coordinates + weighed printed mass | `rerun_logocv_param_ablation.py --variant six-param` |
  | `ablation-shape-only/` | 5: shape coordinates | `rerun_logocv_param_ablation.py --variant shape-only` |
  | `sim-features-shape-sim/` | 5 shape + 6 sim features | `rerun_logocv_sim_features.py --variant shape-sim` |
  | `sim-features-twelve-sim/` | 12 + 6 sim features | `rerun_logocv_sim_features.py --variant twelve-sim` |
  | `sim-features-sim-only/` | 6 sim features alone | `rerun_logocv_sim_features.py --variant sim-only` |

  Each directory holds the campaign-format `t3-prism-bo-round5-logocv.csv`
  (one row per article and objective: observed mean and SEM, held-out
  posterior mean and sd), Ax's `...-diagnostics.json`, and the run's
  `state.json` (settings, seed scheme, per-fold timings). `full-nuts-rerun/`
  also keeps `folds.jsonl`, the per-fold checkpoint with every article's
  full parameterization, which is where `article-features.csv` takes the
  twelve campaign parameters from.

## Produced on this branch

- `ax-six-sim/`: the new Ax run, six original parameters plus the six
  simulation features (12 parameters, none a print-process setting), by
  `../rerun_logocv_six_param_sim.py --variant six-sim` under the same
  protocol as the vendored runs (fold order asserted equal to
  `full-nuts-rerun`, same per-fold seeds, four queue workers at one torch
  thread each, one commit per fold). Same layout as the vendored runs plus
  `folds.jsonl`.
- `article-features.csv`: one row per LOGO article (44): print id, Ax arm,
  design fold key and fold index, print session, the twelve campaign
  parameters exactly as Ax fitted them, the six simulation features, and
  the observed mean and SEM of both objectives. Built by
  `../logocv_baselines.py --build-table`, which asserts the observed values
  equal `manuscript/data/t3-prism-bo-round5-logocv.csv`.
- `baselines/<model>-<space>.csv`: scikit-learn baselines fitted under the
  identical leave-one-design-out protocol, in the campaign CSV layout, with a
  `<model>-<space>-fits.json` recording the hyperparameters each fold chose
  (`../logocv_baselines.py --fit`). Models and spaces are defined in that
  script's docstring.

## Produced on this branch: Ax default, BoFire and the noise diagnostics

PR #121 follow-up (sgbaird, 2026-11-05): "try also with Ax default and
separately also BoFire". Every run below uses the 35 design folds, 44
articles and observed values of the runs above.

- `ax-default-<space>/` (`six`, `six-sim`, `twelve`): Ax 0.5.0's default
  model, i.e. the BoTorch step of `choose_generation_strategy` (what
  `AxClient` builds when no generation strategy is given):
  `Models.BOTORCH_MODULAR`, default surrogate `SingleTaskGP` (BoTorch 0.13
  default priors, MAP fit), transforms `Winsorize` + the SAASBO stack. The
  archived SEMs enter as known noise (`FixedNoiseGaussianLikelihood`), as they
  do whenever Ax is given SEMs. By `../rerun_logocv_six_param_sim.py --model
  ax-default --variant <space>`.
- `ax-registry-<space>/`: the same GP with the registry transforms (no
  `Winsorize`), i.e. the SAASBO run with only the model class changed
  (`--model ax-registry`).
- `ax-default-inferred-noise-<space>/`: Ax default with the SEMs blanked
  (`sem = NaN`), so the GP learns one noise level per objective
  (`--model ax-default --noise inferred`).
- `ax-saasbo-inferred-noise-<space>/`: SAASBO at 256/512 with the SEMs
  blanked (`--model saasbo --noise inferred`); per-fold seeds as in the
  archived runs. `ax-saasbo-inferred-noise-six-sim/` holds only the
  campaign-format CSV: its run finished in a job whose push failed, and the
  CSV was restored from that job's PR comment (PR #121, 2026-11-05). The
  same command regenerates it with `folds.jsonl`, `state.json` and the
  diagnostics (same seeds, about 20 minutes on three workers).

  Each Ax directory has the layout of `ax-six-sim/`. For the MAP models each
  `folds.jsonl` record also carries `hyperparameters` (fitted lengthscales
  on the unit cube, likelihood type, learned noise where there is one), and
  `state.json` carries `model_info` (the generation strategy, transforms,
  Winsorize cutoffs, full-data fit). The MAP refits use
  `warm_start_refit=False` (each fold starts from the prior, not from the
  full-data optimum); a check with Ax's warm start moved rho_s by at most
  0.04.
- `bofire/`: BoFire 0.5.0's default surrogate (`SingleTaskGPSurrogate`, one
  per objective, data-model defaults, noise learned), by
  `../logocv_bofire.py`: `bofire-<space>.csv` (campaign layout; `predicted_sem`
  is the latent sd, `predicted_sd_bofire` is BoFire's own `predict()` sd with
  the learned noise added), `bofire-<space>-fits.json` (per fold and
  objective: lengthscales, learned noise, seconds), `state.json` (versions,
  the resolved data-model defaults).
- `bofire-saas/`: BoFire 0.5.0's fully Bayesian SAAS surrogate
  (`FullyBayesianSingleTaskGPSurrogate`, `model_type="saas"`, one per
  objective, noise learned) at 512 warmup steps / 256 samples / thinning 16,
  the budget of every SAASBO run here, by `../logocv_bofire_saas.py` (PR #121
  follow-up, sgbaird, 2026-11-10). `folds/<space>/<fold_index>.json` holds
  each fold as it finished (held-out rows, per-objective summaries of the 16
  retained draws, seconds); `bofire-saas-<space>.csv` (campaign layout;
  `predicted` and `predicted_sem` are the mean and latent sd of the mixture
  over the draws, `predicted_sd_bofire` is BoFire's own `predict()` sd with
  the learned noise added); `bofire-saas-<space>-fits.json` (per fold and
  objective: median lengthscales over the draws on the unit cube, median
  learned noise and outputscale, seconds); `state.json` (versions, budget,
  seeds, the resolved data model).
- `bofire-saas-default-budget/`: the same at BoFire's own default NUTS
  budget (256 warmup steps / 128 samples / thinning 16, so 8 draws;
  `--budget bofire`), same layout.
- `bofire-saas-lengthscales.json`: per BoFire SAAS run and objective, the
  median over the 35 folds of each input's median lengthscale, and the median
  learned noise as a standardized variance and as an sd in the objective's
  units (by `../logocv_baselines.py --score`).
- `fit-space-bounds.json`: the input bounds every run fits in (the campaign's
  `fit_search_space` for the twelve parameters, the padded observed range for
  the six simulation features), so that BoFire's domain matches Ax's search
  space.
- `map-gp-lengthscales.json`: per MAP GP run and objective, the median fitted
  lengthscale of each input over the 35 folds, the share of folds at BoTorch's
  0.025 lengthscale floor, and the median learned noise (by
  `../logocv_baselines.py --score`).
